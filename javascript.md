# **JavaScript**

## Введение в JavaScript ##

Изначально JavaScript был создан, чтобы сделать веб-страницы живыми:программы на этом языке называются скриптами, встраиваются в HTML и выполняются автоматически при загрузке страницы как простой текст, без специальной подготовки или компиляции, что отличает его от языка Java

## Почему JavaScript ##

При создании язык назывался LiveScript, но из-за популярности Java его переименовали для позиционирования как «младшего брата», хотя сегодня это полностью независимый язык со своей спецификацией ECMAScript:теперь он выполняется не только в браузере, но и на серверах или любых устройствах со специальным «движком» (виртуальной машиной JavaScript), кодовые имена которых полезно знать для понимания совместимости технологий:V8 в Chrome, Opera и Edge; SpiderMonkey в Firefox; Chakra для IE; JavaScriptCore и Nitro для Safari

## Как работают движки ##

Встроенный или внешний движок сначала читает (парсит) текст скрипта, затем преобразует (компилирует) его в машинный язык, после чего запускает быстрый машинный код:на каждом этапе применяются оптимизации, включая анализ проходящих данных прямо во время работы для ускорения выполнения программы

## Что может JavaScript в браузере ##

Это безопасный язык без низкоуровневого доступа к памяти или процессору, возможности которого зависят от окружения (в Node.js доступны чтение файлов и сетевые запросы):в браузере он может изменять HTML-код, содержимое и стили страницы, реагировать на любые действия пользователя, отправлять сетевые запросы через AJAX/COMET, управлять куки, показывать сообщения и сохранять данные на стороне клиента в local storage

## Чего НЕ может JavaScript в браузере ##

Для безопасности пользователя возможности ограничены, чтобы вредоносные страницы не получили доступ к личной информации:скрипты не могут читать и писать произвольные файлы на жестком диске без явных действий пользователя вроде перетаскивания файла или выбора через input, не имеют прямого доступа к ОС, а работа с камерой и микрофоном требует явного разрешения; действует политика одинакового источника (Same Origin Policy), запрещающая окнам и вкладкам с разных сайтов обмениваться данными без специального кода; также ограничена способность получать данные с других доменов без их HTTP-согласия, но эти ограничения не действуют вне браузера

## Что делает JavaScript особенным ##

У языка есть три уникальные сильные стороны, сочетание которых не встречается в других технологиях:полная интеграция с HTML/CSS, простота реализации базовых вещей, а также поддержка всеми основными браузерами, где он включен по умолчанию как самый распространенный инструмент создания интерфейсов

## Языки над JavaScript ##

Для разных нужд созданы новые языки, которые транспилируются (конвертируются) под капотом в JavaScript перед запуском в браузере:CoffeeScript добавляет лаконичный «синтаксический сахар» для Ruby-программистов; TypeScript от Microsoft добавляет строгую типизацию для сложных систем; Flow от Facebook тоже добавляет типизацию, но другим способом; Dart от Google требует транспиляции для браузера, но имеет свой движок для мобильных приложений; Brython транспилирует Python в JavaScript для написания кода без JS, но знание самого JavaScript все равно необходимо для понимания работы системы

# **Справочники и спецификации**

## Спецификация ##

Самую глубокую, детальную и формализованную информацию о JavaScript содержит спецификация ECMA-262, которая определяет сам язык:из-за формального стиля она может показаться сложной и не подходит для ежедневного использования, но является главным источником самой достоверной информации. Новая версия стандарта выходит каждый год, актуальный черновик доступен на tc39.es/ecma262, а посмотреть возможности на стадии добавления (stage 3 proposals) можно в репозитории github.com

## Справочники ##

Главным справочником с примерами и подробными сведениями о функциях языка и методах встроенных объектов является MDN JavaScript Reference от Mozilla:он доступен по адресу developer.mozilla.org/ru/docs/Web/JavaScript/Reference, но на практике для быстрого поиска часто удобнее использовать интернет-поисковик с запросом вида «MDN [название функции]»

## Таблицы совместимости ##

Поскольку JavaScript постоянно развивается, для проверки поддержки новых возможностей в разных браузерах и движках используются специальные ресурсы:сайт caniuse.com предоставляет таблицы поддержки по конкретным технологиям, а на kangax.github.io/compat-table собрана детальная таблица с перечнем всех возможностей языка и совместимых с ними движков

# **Редакторы кода**

## IDE ##

Интегрированная среда разработки (IDE) — это мощный инструмент, который работает на уровне целого проекта и объединяет множество функций:она позволяет переключаться между файлами, предлагает автодополнение по всему коду, а также интегрирована с системами контроля версий вроде git и средами для тестирования. Популярными кроссплатформенными вариантами являются Visual Studio Code и WebStorm (бесплатная для некоммерческого использования), а для платформы .NET на Windows существует мощная платная среда Visual Studio с бесплатной версией Community

## Легкие редакторы ##

«Легкие» редакторы отличаются высокой скоростью работы, простым интерфейсом и запускаются гораздо быстрее, так как не анализируют структуру всего проекта при старте:их используют для быстрого редактирования отдельных файлов, хотя за счет обилия плагинов на автодополнение и синтаксический анализ границы между ними и IDE часто размыты. Среди них выделяются кроссплатформенный Sublime Text, Notepad++ для Windows, а также Vim и Emacs, требующие специальных навыков использования

## Не будем ссориться ##

Выбор редактора кода является исключительно индивидуальным решением программиста:он зависит от конкретных задач, привычек и личных предпочтений, поэтому можно использовать любой инструмент, который кажется наиболее удобным и эффективным для работы

# **Консоль разработчика**

## Инструменты разработки ##

По умолчанию ошибки в коде не видны в браузере, поэтому для их поиска и исправления используются встроенные инструменты разработки (devtools):подавляющее большинство программистов выбирают Chrome и Firefox из-за их высокого качества, используя остальные браузеры только для отлова специфичных ошибок. Devtools позволяют смотреть логи, отслеживать сбои и запускать JavaScript-команды на лету

## Google Chrome ##

Открыть панель инструментов разработчика можно нажатием клавиши F12 или комбинацией Cmd+Opt+J на Mac, после чего по умолчанию отобразится вкладка Console (консоль):сообщения об ошибках подсвечиваются красным цветом, а справа от них выводится ссылка на исходный файл с точным номером строки кода. Синий символ > обозначает командную строку, где можно вводить JS-код и запускать его по кнопке Enter

## Многострочный ввод ##

Если при обычном нажатии Enter введенная команда сразу выполняется, то для переноса строки без запуска кода используется комбинация Shift+Enter:это позволяет разработчику писать и форматировать более длинные и сложные JavaScript-скрипты прямо в консоли перед отправкой

## Firefox, Edge и другие ##

В большинстве современных браузеров на операционной системе Windows инструменты разработчика запускаются аналогично по нажатию кнопки F12:внешний вид интерфейса и базовые принципы работы консоли в них практически идентичны, поэтому после освоения devtools в одном браузере можно легко переключиться на любой другой

## Safari ##

Для работы в браузере Safari на компьютерах Mac консоль требует предварительной активации:необходимо открыть Настройки (Preferences), перейти во вкладку Продвинутые (Advanced) и включить чекбокс отображения меню разработки в строке меню. После этого консоль будет открываться нажатием клавиш Cmd+Opt+C, а в верхнем меню появится раздел Разработка (Develop) со всеми инструментами

# **Основы JavaScript**

# **Привет, мир!**

## Тег script ##

Для запуска скриптов в браузере программы на языке JavaScript вставляются в любое место HTML-документа с помощью тега :код внутри этого тега выполняется автоматически, как только браузер его обработает, в то время как в серверных средах (например, в Node.js) файл запускается через терминал командой типа node my.js. Пример вставки скрипта на страницу:

```
<!DOCTYPE HTML>
<html>
<body>
  <p>Перед скриптом...</p>
  <script>
    alert( 'Привет, мир!' );
  </script>
  <p>...После скрипта.</p>
</body>
</html>
```

## Современная разметка ##

В современном HTML старые атрибуты тега  стали необязательными и практически не используются:атрибут script type="..." раньше требовал значения "text/javascript", а сейчас применяется для модулей; атрибут script language="..." утратил смысл, так как JavaScript активен по умолчанию. Также больше не требуется обертывание скрипта в HTML-комментарии, которое использовалось в древнем коде для скрытия текста от старых браузеров:

```
<script type="text/javascript"><!--
    ...
//--></script>
```

## Внешние скрипты ##

Сложный и объемный JavaScript-код принято выносить в отдельные файлы и подключать к HTML с помощью атрибута src:это позволяет указывать абсолютный путь от корня, относительный путь вроде src="script.js" или полный URL-адрес. Польза отдельных файлов в том, что браузер кэширует их, загружая из сети только один раз, что экономит трафик и ускоряет работу сайта. Примеры подключения:

```
html<script src="/path/to/script.js"></script>
<script src="https://cloudflare.com"></script>
```

## Ограничение атрибута src ##

При подключении внешнего файла необходимо помнить важное правило:если у тега  установлен атрибут src, то любое встроенное внутрь этого тега текстовое содержимое будет полностью игнорироваться браузером:

```
<script src="file.js">
  alert(1); // содержимое игнорируется, так как есть атрибут src
</script>
```

Чтобы использовать и внешний файл, и внутренний код одновременно, их нужно разделить на два отдельных тега:

```
<script src="file.js"></script>
<script>
  alert(1);
</script>
```

# **Структура кода**

## Инструкции ##

Инструкции — это синтаксические конструкции и команды, выполняющие действия в коде (например, вывод сообщения на экран):в скрипте можно писать неограниченное количество инструкций, разделяя их точкой с запятой. Для улучшения читаемости кода каждую инструкцию принято располагать на новой строке:

```
alert('Привет');
alert('Мир');
```

## Точка с запятой ##

В большинстве случаев точку с запятой можно опустить, если выражение завершается переносом строки, так как движок JavaScript интерпретирует его как неявный знак:это называется автоматической вставкой точки с запятой. Перенос строки не сработает как разделитель, если выражение явно не завершено (например, заканчивается на знак плюс), но в некоторых ситуациях движок «забывает» сделать вставку, что приводит к критическим ошибкам:

```
alert(3 +
1
+ 2); // Код выведет 6, точка с запятой не вставилась из-за знака "+"
```

## Пример ошибки автоматической вставки ##

Если не поставить точку с запятой перед квадратными скобками, движок JavaScript не распознает перенос строки и сольет две разные инструкции в одну, из-за чего скрипт упадет с ошибкой в консоли: 

```
// Этот код вызовет ошибку:
alert('Hello')
[1, 2].forEach(alert);

// Движок видит это так: alert('Hello')[1, 2].forEach(alert);
```

Во избежание подобных трудночитаемых багов в сообществе разработчиков настоятельно рекомендуется всегда явно ставить точку с запятой между инструкциями.

## Комментарии ##

Комментарии служат для пояснения логики кода, полностью игнорируются движком при выполнении и могут быть однострочными (начинаются с //) или многострочными (ограничиваются символами /* и */):

```
/ Этот комментарий занимает всю строку
alert('Привет');

/* Пример с двумя сообщениями.
Это - многострочный комментарий.
*/
alert('Мир'); // Этот комментарий следует за инструкцией
```

Многострочные комментарии удобно использовать для временного отключения участков кода при отладке, однако они строго не поддерживают вложенность — конструкция /* /* ... */ */ приведет к поломке скрипта.

## Использование горячих клавиш и минификация ##

В современных редакторах кода для быстрого комментирования строк используются комбинации клавиш Ctrl + / (для одной строки) и Ctrl + Shift + / (для блока кода), а на системах Mac клавиша Ctrl заменяется на Cmd:

```
/* Закомментировали код, который не должен работать:
alert('Привет');
*/
alert('Мир');
```

Наличие комментариев увеличивает объем исходного файла, но никак не влияет на производительность и трафик, так как перед деплоем на продакшен-сервер специальные инструменты минификации автоматически удаляют весь сопутствующий текст из рабочих скриптов

# **Строгий режим — "use strict"**

## use strict ##

Для сохранения обратной совместимости старые ошибки JavaScript оставались в языке навсегда, пока в 2009 году стандарт ECMAScript 5 (ES5) не ввел новые правила, изменяющие поведение старых функций:чтобы активировать современный режим и не сломать устаревший код, необходимо явно использовать директиву "use strict" или 'use strict'. Строка должна находиться в самом начале скрипта, делая его полностью «современным», либо в начале тела функции для изоляции режима:

```
"use strict";

// этот код работает в современном режиме
...
```

## словия включения и необратимость ##

Директива "use strict" должна быть строго первой исполняемой строкой в коде, иначе движок проигнорирует ее и современный режим не активируется:выше директивы допускается размещать исключительно комментарии. Кроме того, в языке отсутствует какая-либо команда отмены вроде "no use strict" — однажды включив строгий режим для файла или функции, вернуться к старому поведению обратно уже невозможно:

```
alert("some code");
// "use strict" ниже игнорируется - он должен быть в первой строке

"use strict";
// строгий режим не активирован
```

## Консоль браузера ##

По умолчанию в консоли инструментов разработчика строгий режим выключен, что может приводить к неверным результатам при тестировании кода:для его включения используют многострочный ввод через Shift+Enter, где первой строкой пишут директиву. В более старых браузерах гарантировать работу режима можно с помощью обертки в самовызывающуюся функцию (IIFE):

```
'use strict'; // Нажать Shift+Enter
// ...ваш код...

// Надежный способ через функцию-обертку:
(function() {
  'use strict';
  // ...ваш код...
})()
```

## Всегда ли нужно использовать use strict ##

На начальном этапе изучения языка рекомендуется вручную прописывать директиву в начале каждого отдельного файла:однако в современном JavaScript продвинутые структуры кода, такие как «классы» и «модули», активируют строгий режим автоматически «под капотом». Когда весь проект пишется с их использованием, необходимость в явном добавлении "use strict" полностью отпадает

# **Переменные**

## Переменная ##

Переменная — это именованное хранилище для данных, которое создается с помощью ключевого слова let, после чего в нее можно поместить информацию через оператор присваивания =:для повышения читаемости кода рекомендуется объявлять каждую переменную на новой строке, а не перечислять их через запятую. Доступ к значению осуществляется по имени переменной:

```
let message;
message = 'Hello!'; // сохранили строку

// Совмещение объявления и записи в одну строку:
let user = 'John';
alert(user); // John
```

## var вместо let ##

В старых скриптах вместо современного ключевого слова let для объявления переменных часто использовалось ключевое слово var:оно работает схожим образом, но представляет собой устаревший подход с рядом тонких отличий в поведении, которые рассматриваются отдельно:

```
var message = 'Hello'; // устаревший способ объявления
```

## Изменение значения и повторное объявление ##

В JavaScript значение одной переменной можно менять любое количество раз — при записи новых данных старые полностью удаляются из памяти:также можно копировать значения из одной переменной в другую. При этом повторное использование ключевого слова let для уже существующего имени приведет к критической ошибке:

```
let message = "Это";
// let message = "Другое"; // SyntaxError: 'message' has already been declared

message = "Новое значение"; // Так правильно, без ключевого слова let
```

## Имена переменных ##

Имя переменной в JavaScript может содержать только буквы, цифры, а также символы $ и _, но первый символ строго не должен быть цифрой:в многословных именах принято использовать верблюжью нотацию (camelCase). Регистр букв имеет значение (apple и APPLE — разные хранилища), кириллица технически разрешена, но не рекомендуется международными стандартами:

```
let $ = 1; 
let _ = 2; // корректные имена
// let 1a = 3; // Ошибка: нельзя начинать с цифры
// let my-name = 4; // Ошибка: дефис запрещен
```

## Зарезервированные имена ##

Существует фиксированный список слов, которые зарезервированы самим языком JavaScript, поэтому их категорически запрещено использовать в качестве названий для собственных переменных:попытка присвоить значение в такое имя вызовет синтаксическую ошибку программы:

```
// let let = 5; // синтаксическая ошибка!
// let function = 5; // синтаксическая ошибка!
```

## Создание переменной без let в строгом режиме ##

В старом JavaScript было возможно создать переменную простым присваиванием значения без использования let или var, что до сих пор работает без директивы "use strict" ради совместимости:однако в строгом режиме подобная небрежность считается плохой практикой и приводит к падению скрипта:

```
"use strict";
// num = 5; // ошибка: num is not defined
```

## Константы ##

Для объявления неизменяемой переменной используется ключевое слово const:перезаписать значение такой переменной невозможно, попытка приведет к ошибке. Константы для жестко закодированных значений, известных до старта скрипта, принято писать заглавными буквами через подчеркивание, а вычисляемые во время работы программы константы именуются в обычном camelCase:

```
const myBirthday = '18.04.1982';
// myBirthday = '01.01.2001'; // ошибка, константу нельзя перезаписать!

const COLOR_RED = "#F00"; // жестко закодированная константа
const pageLoadTime = 125; // константа, вычисленная в процессе выполнения
```

## Правила именования и отказ от повторного использования ##

Имя переменной должно быть максимально описательным, лаконичным и четко отражать суть хранящихся в ней данных:следует избегать бессмысленных имен вроде data или value, коротких букв a, b, c и аббревиатур. Нельзя экономить на переменных и использовать одну «коробку» для хранения разных по смыслу данных — создание отдельных переменных улучшает читаемость и помогает движку оптимизировать код

# **Типы данных**

## Динамическая типизация ##

Значение в JavaScript всегда относится к данным определённого типа, однако сам язык является динамически типизированным:переменные не привязаны намертво ни к одному типу данных, поэтому в один момент хранилище может содержать строку, а затем в него можно без ошибки записать число:

```
let message = "hello";
message = 123456; // тип данных изменился с string на number
```

## Число (number) ##

Числовой тип данных представляет как целочисленные значения, так и числа с плавающей точкой, поддерживая стандартные математические операции:помимо обычных чисел, к этому типу относятся специальные значения Infinity (математическая бесконечность, получаемая в том числе при делении на ноль) и NaN (вычислительная ошибка, возникающая при некорректных операциях). Значение NaN «прилипчиво» — любая математическая операция с ним возвращает NaN (за исключением NaN ** 0, что дает 1), при этом любые вычисления в JavaScript безопасны и никогда не приводят к фатальной ошибке скрипта:

```
alert( 1 / 0 ); // Infinity
alert( "не число" / 2 ); // NaN
alert( NaN + 1 ); // NaN
```

## BigInt ##

Стандартный тип number не может безопасно хранить нечетные целые числа за пределами диапазона от -(253-1) до (253-1) из-за ограничений 64-битной памяти, что приводит к ошибкам точности при работе с гигантскими значениями:для криптографии и микросекундных меток времени используется тип BigInt, позволяющий работать с целыми числами произвольной длины. Чтобы создать такое число, необходимо добавить символ n в конец числового литерала:

```
// большие числа типа number теряют точность:
console.log(9007199254740991 + 1); // 9007199254740992
console.log(9007199254740991 + 2); // 9007199254740992

const bigInt = 1234567890123456789012345678901234567890n; // BigInt
```

## Строка (string) ##

Строки в JavaScript обязательно заключаются в кавычки, которых существует три вида: одинарные, двойные и обратные:одинарные и двойные кавычки являются простыми и не отличаются по функционалу, в то время как обратные кавычки позволяют встраивать переменные или математические выражения прямо внутрь строки через конструкцию ${...}. Отдельного символьного типа (вроде char) в языке нет — одиночные символы тоже являются строками:

```
let name = "Иван";
alert( `Привет, ${name}!` ); // Привет, Иван!
alert( `результат: ${1 + 2}` ); // результат: 3
alert( "результат: 1 + 2" ); // результат: {1 + 2} (двойные кавычки не вычисляют код)
```
 
## Булевый тип (boolean) ##

Логический тип данных может принимать исключительно два значения: true (истина) и false (ложь):он используется для хранения ответов на вопросы вида «да/нет», а также генерируется автоматически в результате работы любых операторов сравнения:

```
let nameFieldChecked = true;
let isGreater = 4 > 1; // true
```

## Значения null и undefined ##

Значения null и undefined стоят особняком и формируют свои собственные одноименные типы данных:значение null означает «ничего», «пусто» или «значение неизвестно», а значение undefined указывает на то, что «значение переменной еще не было присвоено». Присваивать undefined вручную не рекомендуется — для явного обнуления принято использовать null:

```
let age = null; // значение неизвестно

let height;
alert(height); // выведет "undefined", так как переменная просто объявлена
```

## Объекты и символы ##

Все вышеперечисленные типы являются «примитивными», так как хранят только одно простое значение, в то время как тип object (объект) служит для организации сложных структур и коллекций данных:отдельный тип symbol (символ) используется внутри объектов для создания уникальных скрытых идентификаторов, повышающих безопасность и структурированность кода.

## Оператор typeof ##

Оператор typeof возвращает тип своего аргумента в виде строки и может использоваться в виде обычного оператора typeof x или в форме вызова со скобками typeof(x):при проверке выражений скобки обязательны из-за высокого приоритета оператора. В работе typeof есть исторические особенности: для null он возвращает "object" (официально признанная ошибка языка), а для функций возвращает "function", хотя встроенного типа «функция» не существует — они технически относятся к объектам:

```
typeof undefined // "undefined"
typeof 0         // "number"
typeof 10n       // "bigint"
typeof "foo"     // "string"
typeof null      // "object" (ошибка в языке)
typeof alert     // "function" (особый случай для функций)

typeof 50 + " Квартир";   // "number Квартир"
typeof (50 + " Квартир"); // "string"
```

# **Взаимодействие: alert, prompt, confirm**

## alert ##

Функция alert используется для вывода информации пользователю и отображает небольшое модальное окно с текстом и кнопкой «ОК»:понятие «модальное» означает, что выполнение скрипта полностью приостанавливается, а пользователь блокируется от любого взаимодействия с остальным интерфейсом веб-страницы до тех пор, пока окно не будет закрыто нажатием на кнопку:

```
alert("Hello"); // показывает окно и ждет нажатия ОК
```

## prompt ##

Функция prompt служит для получения текстовых данных от пользователя и принимает два аргумента, возвращая введенную строку либо специальное значение null:

```
result = prompt(title, [default]);
```

Первый параметр title задает текст вопроса в окне, а необязательный второй параметр default устанавливает начальное значение в поле ввода. Если пользователь нажимает «ОК», переменной присваивается набранный текст, а при нажатии «Отмена» или клавиши Esc возвращается null. В старых браузерах вроде Internet Explorer отсутствие второго параметра приводит к багу со вставкой строки "undefined", поэтому для кроссбраузерности там всегда рекомендуется передавать хотя бы пустую строку:

```
let age = prompt('Сколько тебе лет?', 100);
alert(`Тебе ${age} лет!`); // Тебе 100 лет!

let test = prompt("Test", ''); // <-- безопасный синтаксис для старых IE
```

## confirm ##

Функция confirm предназначена для получения от пользователя подтверждения на действие и выводит модальное окно с текстом вопроса и двумя кнопками: «ОК» и «Отмена»:вызов возвращает логическое значение true, если пользователь согласился и нажал кнопку «ОК», и значение false в случае нажатия «Отмена» или отмены окна клавишей Esc:

```
let isBoss = confirm("Ты здесь главный?");
alert( isBoss ); // true, если нажата OK, иначе false
```

## Ограничения модальных окон ##

Все три функции встроены на уровне браузера, что дает им предельную простоту использования, но накладывает два жестких ограничения:разработчик не может программно изменить внешний вид, стили или шрифты этих окон, так как их дизайн целиком зависит от операционной системы и браузера, а точное геометрическое расположение окон на экране (обычно по центру) также определяется исключительно браузером без возможности кастомизации

# **Преобразование типов**

## Строковое преобразование ##

Строковое преобразование происходит автоматически при выводе данных методами вроде alert(value) или вызывается явно с помощью функции String(value):для примитивных значений этот процесс работает очевидным образом, превращая логические типы, null или числа в их текстовые аналоги в кавычках:

```
let value = true;
alert(typeof value); // boolean

value = String(value); // теперь value это строка "true"
alert(typeof value); // string
```

## Численное преобразование ##

Численное преобразование автоматически запускается в математических функциях и выражениях при использовании операторов вроде деления /:для явного приведения строки или другого примитива к числу применяется функция Number(value), которая часто используется для обработки текстовых полей веб-форм. Если входящая строка содержит нечисловые символы, результатом вычисления становится NaN:

```
alert( "6" / "2" ); // 3, строки автоматически преобразовались в числа

let str = "123";
let num = Number(str); // становится числом 123
alert(typeof num); // number

let age = Number("Любая строка вместо числа"); // NaN, преобразование не удалось
```

## Правила численного преобразования ##

При конвертации примитивов в числа действуют строгие правила, где особое внимание стоит обратить на разницу между null и undefined:значение undefined превращается в NaN, значение null становится нулем 0, логические true / false трансформируются в 1 / 0 соответственно. При обработке строк пробельные символы, знаки табуляции \t и переноса строки \n по краям автоматически обрезаются; пустая строка дает 0, а любая ошибка чтения текста возвращает NaN:

```
alert( Number(undefined) );   // NaN
alert( Number(null) );        // 0
alert( Number(true) );        // 1
alert( Number("   123   ") ); // 123
alert( Number("123z") );      // NaN (ошибка чтения на символе "z")
```

## Логическое преобразование ##

Логическое преобразование выполняется неявно в условных конструкциях или явно через вызов функции Boolean(value):все пустые или ошибочные с точки зрения логики значения (0, пустая строка "", null, undefined, NaN) всегда превращаются в false. Любые остальные заполненные значения переходят в статус true:

```
alert( Boolean(1) ); // true
alert( Boolean(0) ); // false
alert( Boolean("Привет!") ); // true
alert( Boolean("") ); // false
```

## Особые случаи логического преобразования ##

В отличие от некоторых других языков программирования, в JavaScript любая непустая строка всегда расценивается как истина:из-за этого правила строка с текстовым нулем "0" или строка, состоящая только из одних пробелов " ", успешно конвертируется в true:

```
alert( Boolean("0") ); // true
alert( Boolean(" ") ); // пробел это тоже true (непустая строка)
```

# **Базовые операторы, математика**

## Терминология ##

Операнд (или аргумент) — это сущность, к которой применяется оператор (например, в выражении 5 * 2 левым операндом является 5, а правым — 2). Операторы делятся на унарные, которые работают с одним операндом, и бинарные, использующие два операнда:

```
let x = 1;
x = -x; // унарный минус меняет знак числа на противоположный (-1)

let y = 3;
alert( y - x ); // бинарный минус выполняет операцию вычитания (4)
```

## Математические операторы ##

JavaScript поддерживает стандартные арифметические действия: сложение +, вычитание -, умножение *, деление /, а также взятие остатка от деления % и возведение в степень **. Оператор % возвращает остаток от целочисленного деления, а оператор ** может возводить числа в том числе в дробную степень, выполняя математическую функцию извлечения корня:

```
alert( 5 % 2 );     // 1 (остаток от деления 5 на 2)
alert( 8 % 3 );     // 2 (остаток от деления 8 на 3)
alert( 2 ** 4 );    // 16 (2 в четвертой степени)
alert( 4 ** (1/2) );// 2 (возведение в степень 1/2 равносильно квадратному корню)
```

## Сложение строк бинарным плюсом ##

Если бинарный оператор + применяется к строкам, он осуществляет их конкатенацию (объединение):при этом если хотя бы один из операндов является строкой, второй операнд автоматически приводится к строковому типу. Вычисления выполняются строго слева направо, поэтому идущие подряд числа сложатся математически до того, как встретят строку:

```
let s = "моя" + "строка"; // "моястрока"
alert( '1' + 2 ); // "12"
alert( 2 + 2 + '1' ); // "41" (сначала 2+2=4, затем 4+'1'="41")
```

Другие арифметические операторы (минус, деление, умножение) работают исключительно с числами и всегда преобразуют любые строки в числовой тип:

```
alert( 6 - '2' ); // 4
alert( '6' / '2' ); // 3
```

## Унарный плюс ##

Унарный плюс +, примененный к одному значению, не оказывает никакого влияния на обычные числа, но мгновенно преобразует любые нечисловые типы данных в числа:данный оператор работает как укороченный аналог функции Number(...) и часто применяется для конвертации строковых значений из HTML-форм перед их математическим сложением:

```
alert( +true ); // 1
alert( +"" );   // 0

let apples = "2";
let oranges = "3";
alert( +apples + +oranges ); // 5 (унарные плюсы сработали до бинарного сложения)
```

## Приоритет операторов ##

Порядок выполнения операций в сложных выражениях регулируется таблицей приоритетов, где каждому оператору присвоен свой цифровой номер (чем выше число, тем быстрее сработает команда):круглые скобки имеют наивысший приоритет и позволяют переопределить стандартный порядок действий. Унарные операторы всегда сильнее своих бинарных аналогов (например, унарный плюс имеет приоритет 15, бинарное сложение — 12, а оператор присваивания = — один из самых низких приоритетов, равный 2):

```
let x = 2 * 2 + 1; // сначала выполнится умножение, затем сложение, в конце присваивание
```

## Специфика оператора присваивания ## 

Оператор присваивания = не является изолированной конструкцией языка, а возвращает записанное им значение, что позволяет внедрять его внутрь сложных математических выражений или выстраивать цепочки присваиваний справа налево:

```
let a = 1;
let b = 2;
let c = 3 - (a = b + 1); // присвоит переменной "a" значение 3 и вернет его для вычисления "c"

let x, y, z;
x = y = z = 2 + 2; // все три переменные получат значение 4
```

## Сокращенная арифметика ##

Для быстрого изменения текущего значения переменной и сохранения нового результата в нее же используются совмещенные операторы вида +=, -=, *=, /=, **=:они обладают тем же низким приоритетом, что и стандартное присваивание, поэтому вся правая часть математического выражения будет вычислена до применения этой команды:

```
let n = 2;
n += 5; // n = 7
n *= 3 + 5; // n *= 8, в результате n станет равным 56
```

## Инкремент и декремент ## 

Операторы инкремента ++ и декремента -- увеличивают или уменьшают переменную ровно на единицу и применимы исключительно к переменным (попытка вызвать 5++ вызовет ошибку):

```
let counter = 2;
counter++; // counter = 3
```

let counter = 2;
counter++; // counter = 3

```
let c1 = 1;
alert( ++c1 ); // 2 (префиксная форма возвращает новый результат)

let c2 = 1;
alert( c2++ ); // 1 (постфиксная форма возвращает старое значение)
```

## Побитовые операторы и запятая ##

Побитовые операторы (&, |, ^, ~, <<, >>, >>>) работают с числами на низком уровне двоичного 32-разрядного представления и применяются преимущественно в специфических задачах вроде криптографии. Редкий оператор «запятая» , позволяет перечислять несколько выражений через запятую — все они последовательно выполняются, но возвращается результат только самого последнего выражения:

```
let a = (1 + 2, 3 + 4); // a = 7 (результат 1+2 отброшен)
```

# **Операторы сравнения**

## Результат сравнения ##

Все операторы сравнения (>, <, >=, <=, ==, !=) всегда возвращают логическое значение: true (истина) или false (ложь). Полученный результат сравнения является стандартным примитивом, поэтому его можно легко присвоить любой переменной:

```
alert( 2 > 1 );  // true
alert( 2 == 1 ); // false

let result = 5 > 4; // результат сравнения сохраняется в переменную
alert( result ); // true
```

## Сравнение строк ##

Для определения того, какая строка больше, JavaScript использует посимвольный лексикографический (алфавитный) порядок. Сравнение идет строго слева направо: сначала оцениваются первые символы, и если они равны, движок переходит ко вторым, продолжая процесс до конца одной из строк. Если символы различаются, большей признается строка с более «сильным» символом; если же одна строка полностью совпадает с началом другой, но длиннее ее — длинная считается большей:

```
alert( 'Я' > 'А' ); // true
alert( 'Коты' > 'Кода' ); // true (буквы "К" и "о" равны, но "т" больше "д")
alert( 'Сонный' > 'Сон' ); // true (первая строка длиннее при полной идентичности начала)
```

## Сравнение разных типов ##

При сравнении значений, имеющих разные типы данных, JavaScript автоматически приводит каждый операнд к числу:логическое true трансформируется в 1, false преобразуется в 0, а текстовые строки также переводятся в цифровой вид:

```
alert( '2' > 1 ); // true (строка '2' становится числом 2)
alert( '01' == 1 ); // true (строка '01' становится числом 1)
alert( true == 1 ); // true
```

alert( '2' > 1 ); // true (строка '2' становится числом 2)
alert( '01' == 1 ); // true (строка '01' становится числом 1)
alert( true == 1 ); // true

```
let a = 0; // Boolean(a) дает false
let b = "0"; // Boolean(b) дает true (строка не пустая)
alert(a == b); // true! (оба операнда превратились в числовой 0)
```

## Строгое сравнение ##

Нестрогое равенство == имеет серьезную проблему: оно не способно отличить число 0 или пустую строку '' от логического флага false, так как принудительно переводит их в нули. Для решения этой проблемы используется оператор строгого равенства === (и аналогичный ему оператор строгого неравенства !==), который проверяет идентичность значений без приведения типов — если типы операндов различаются, проверка мгновенно возвращает false:

```
alert( 0 === false ); // false (строгое равенство, так как типы number и boolean разные)
```

## Сравнение с null и undefined ##

Значения null и undefined ведут себя изолированно и подчиняются специфическим правилам языка. При строгом сравнении === они не равны, поскольку относятся к разным типам данных, однако при нестрогом сравнении == они равны строго друг другу и категорически не равны больше никаким другим значениям в системе:

```
alert( null === undefined ); // false
alert( null == undefined ); // true
alert( null == 0 ); // false (null не равен нулю при нестрогом равенстве)
```

При использовании же математических операторов или стандартных операторов сравнения (>, <, >=, <=) эти значения ведут себя иначе и переводятся в числа: null становится полноценным нулем 0, а undefined превращается в вычислительную ошибку NaN.

## Причуды null и undefined в сравнениях ##

Из-за разделения логики работы == и математических знаков сравнения возникают парадоксальные результаты при сопоставлении null с нулем:

```
alert( null > 0 );  // false (1) математика превращает null в 0, выражение 0 > 0 ложно
alert( null == 0 ); // false (2) правило == запрещает null приводиться к числу
alert( null >= 0 ); // true  (3) математика превращает null в 0, выражение 0 >= 0 истинно
```

Значение undefined при этом является полностью несравнимым с любыми числами. Любое математическое сравнение с ним возвращает false, потому что undefined становится NaN, а NaN всегда выдает ложь при любых проверках. Нестрогое равенство с нулем также ложно, поскольку undefined имеет право быть равным только null или самому себе:

```
alert( undefined > 0 ); // false (NaN > 0)
alert( undefined < 0 ); // false (NaN < 0)
alert( undefined == 0 ); // false (не равен по спецправилу)
```

## Как избежать ошибок ##

Чтобы обезопасить свой код от неожиданных багов, связанных с особенностями динамической типизации JavaScript, рекомендуется соблюдать два надежных правила разработки:всегда использовать строгое равенство === вместо обычного ==, а также никогда не применять математические операторы сравнения (>, <, >=, <=) к переменным, которые потенциально могут содержать внутри себя значения null или undefined, предварительно изолируя такие случаи явными проверками.

# **Условное ветвление: if, '?'**

## Инструкция if ##

Инструкция if(...) принимает выражение в скобках, вычисляет его и выполняет блок кода, если итоговый результат равен true. При написании нескольких команд их в обязательном порядке необходимо группировать в фигурные скобки {} — в сообществе разработчиков их настоятельно рекомендуется использовать даже для одной инструкции ради повышения читаемости:

```
let year = prompt('В каком году была опубликована спецификация ECMAScript-2015?', '');

if (year == 2015) {
  alert( "Правильно!" );
  alert( "Вы такой умный!" );
}
```

## Преобразование условий к логическому типу ##

Выражение внутри круглых скобок if (...) автоматически преобразуется движком к булевому типу на основании стандартных правил. Число 0, пустая строка "", null, undefined и NaN всегда превращаются в false (их называют ложными или «falsy» значениями), из-за чего код в таком блоке никогда не выполнится. Все остальные значения становятся true (правдивые или «truthy» значения), также в проверку можно передавать заранее вычисленные флаги из переменных:

```
if (0) { 
  // этот код никогда не выполнится
}

let condition = (year == 2015); // содержит true или false
if (condition) {
  // выполнится, если condition истинно
}
```

## Блоки else и else if ##

Инструкция if может быть расширена необязательным блоком else («иначе»), который автоматически срабатывает, когда основное условие оказывается ложным. Для последовательной проверки нескольких альтернативных вариантов условий применяется цепочка блоков else if, которая прекращает перебор, как только встретит первое истинное выражение:

```
let year = prompt('В каком году была опубликована спецификация ECMAScript-2015?', '');

if (year < 2015) {
  alert( 'Это слишком рано...' );
} else if (year > 2015) {
  alert( 'Это поздновато' );
} else {
  alert( 'Верно!' ); // сработает, если прошлые проверки выдали false
}
```

## Условный оператор "?" ##

Для короткого присвоения значения в переменную на основании условия используется оператор вопросительного знака ?, называемый тернарным, так как он принимает три аргумента. Синтаксис конструкции выглядит как условие ? значение1 : значение2. Круглые скобки вокруг условия технически можно опустить из-за низкого приоритета тернарного оператора, но их рекомендуется оставлять для наглядности:

```
let age = prompt('Сколько вам лет?', '');
let accessAllowed = (age > 18) ? true : false;

// В данном случае тернарный оператор избыточен, так как сравнение само возвращает true/false:
let accessAllowedShort = age > 18;
```

## Множественные операторы "?" ##

Последовательное объединение нескольких знаков вопроса позволяет построить ветвление, возвращающее одно конкретное значение из множества вариантов в зависимости от комплексных условий. Движок выполняет проверку по цепочке сверху вниз, считывая двоеточие : как команду перехода к следующему шагу при ложном исходе предыдущего:

```
let age = prompt('Возраст?', 18);

let message = (age < 3) ? 'Здравствуй, малыш!' :
  (age < 18) ? 'Привет!' :
  (age < 100) ? 'Здравствуйте!' :
  'Какой необычный возраст!';

alert( message );
```

## Нетрадиционное использование тернарного оператора ##

Иногда оператор ? ошибочно применяют вместо полноценного if для непосредственного запуска функций или методов (например, вызова alert) без присвоения результата в переменную. Подобный стиль разработки настоятельно не рекомендуется, поскольку он нарушает вертикальное восприятие структуры кода и сильно снижает общую читаемость проекта:

```
let company = prompt('Какая компания создала JavaScript?', '');

// Плохой тон:
(company == 'Netscape') ? alert('Верно!') : alert('Неправильно.');

// Хороший тон (код легко сканируется глазами):
if (company == 'Netscape') {
  alert('Верно!');
} else {
  alert('Неправильно.');
}
```

# **Логические операторы**

## Оператор ИЛИ (||) ##

В традиционном программировании оператор «ИЛИ» || обрабатывает булевые значения и возвращает true, если хотя бы один из аргументов истинен. Если операнд имеет другой тип данных, для проведения вычислений он временно приводится движком к логическому формату (например, число 1 воспринимается как true, а 0 — как false):

```
alert( true || false );  // true
alert( false || false ); // false

if (1 || 0) { // сработает как true || false
  alert( 'истинно!' );
}
```

## Расширенный алгоритм ИЛИ (||) ##

В JavaScript оператор || обладает дополнительными возможностями и при работе с цепочкой из нескольких значений вычисляет операнды слева направо. Движок конвертирует каждый элемент в логический тип, и как только встречает первое истинное («truthy») значение, он мгновенно останавливает вычисления и возвращает этот операнд в его исходном виде. Если все элементы в цепочке оказались ложными («falsy»), оператор возвращает самый последний операнд:

```
alert( null || 1 ); // 1 (первое истинное значение)
alert( null || 0 || 1 ); // 1
alert( undefined || null || 0 ); // 0 (все ложно, вернулось последнее значение)

// Получение первого заполненного значения из списка переменных:
let firstName = "";
let lastName = "";
let nickName = "Суперкодер";
alert( firstName || lastName || nickName || "Аноним"); // "Суперкодер"
```

## Логическое присваивание ИЛИ (||=) ##

Оператор логического присваивания ||= представляет собой «синтаксический сахар» для сокращения условных проверок. Конструкция a ||= b вычисляет операнды и присваивает переменной a значение b только в том случае, если исходное значение a является ложным (false, 0, пустая строка и т.д.):

```
let johnHasCar = false;
johnHasCar ||= "У Джона нет машины!"; 
alert( johnHasCar ); // "У Джона нет машины!"

// Эквивалентно классической записи через инструкцию if:
let manufacturer = "";
if (manufacturer == false) {
  manufacturer = "Неизвестный производитель";
}
```

## Оператор И (&&) ##

Оператор «И» && возвращает true только тогда, когда оба его операнда истинны, а во всех остальных случаях выдает false:

```
let hour = 12;
let minute = 30;
if (hour == 12 && minute == 30) {
  alert( 'Время 12:30' );
}
```

## Расширенный алгоритм И (&&) ##

При переборе цепочки условий оператор && работает противоположно оператору || — он сканирует операнды слева направо, преобразует их в булевый тип и останавливает работу на первом же ложном («falsy») значении, возвращая его исходный вариант. Если абсолютно все операнды в цепочке оказались истинными, оператор возвращает значение самого последнего из них:

```
alert( 1 && 0 ); // 0 (первое ложное значение)
alert( null && 5 ); // null (первое ложное, второй операнд проигнорирован)
alert( 1 && 2 && null && 3 ); // null

alert( 1 && 2 && 3 ); // 3 (все истинны, вернулось последнее)
```

## Логическое присваивание И (&&=) ##

Оператор &&= работает по аналогичному принципу сокращенного вычисления, но выполняет запись значения с точностью до наоборот. Конструкция a &&= b присвоит переменной a значение b исключительно в том случае, если текущее значение a является истинным («truthy»):

```
let greeting = "Привет";
greeting &&= greeting + ", пользователь!";
alert( greeting ); // "Привет, пользователь!"
```

На практике оператор &&= используется довольно редко, поскольку контекст для его эффективного применения в реальном коде подобрать значительно сложнее, чем для ||=.

## Оператор НЕ (!) ##

Унарный оператор «НЕ» ! имеет наивысший приоритет среди всех логических операторов, поэтому всегда вычисляется первым. Он принимает один аргумент, принудительно приводит его к логическому типу true/false и возвращает строго противоположное значение. Для быстрого преобразования любого типа данных в булевый формат используют двойное отрицание !!, которое работает идентично вызову встроенной функции Boolean():

```
alert( !true ); // false
alert( !0 );    // true

alert( !!"непустая строка" ); // true (первое НЕ дало false, второе инвертировало в true)
alert( !!null );             // false
```

# **Операторы нулевого слияния и присваивания: '??', '??='**

## Оператор нулевого слияния (??) ##

Оператор нулевого слияния ?? используется для выбора первого «определенного» значения из списка. В контексте этого оператора значение считается определенным, если оно строго не равняется ни null, ни undefined. Выражение a ?? b мгновенно возвращает a, если оно определено, в противном случае результатом вычисления становится b:

```
let user;
alert(user ?? "Аноним"); // "Аноним" (переменная user не определена)

let activeUser = "Иван";
alert(activeUser ?? "Аноним"); // "Иван" (переменная существует и определена)
```

Под капотом эта конструкция заменяет собой громоздкую запись через тернарный оператор: result = (a !== null && a !== undefined) ? a : b. С помощью ?? можно выстраивать цепочки для последовательного поиска первого заполненного хранилища:

```
let firstName = null;
let lastName = null;
let nickName = "Суперкодер";

alert(firstName ?? lastName ?? nickName ?? "Аноним"); // "Суперкодер"
```

## Разница между ?? и || ##

Главное отличие между старым оператором ИЛИ || и новым оператором нулевого слияния ?? заключается в строгости отбора:
* Оператор || возвращает первое истинное (truthy) значение.
* Оператор ?? возвращает первое определенное (не null/undefined) значение.

Оператор || не видит разницы между false, числом 0, пустой строкой "" и техническими значениями null/undefined — для него они все являются «ложными» (falsy). На практике числовой ноль часто является корректным рабочим результатом, который нельзя заменять значением по умолчанию, и в таких ситуациях ?? работает правильно:

```
let height = 0;

alert(height || 100); // 100 (бинарный плюс увидел в 0 ложь и вернул дефолт)
alert(height ?? 100); // 0 (нулевое слияние видит, что 0 определен, и оставляет его)
```

## Приоритет оператора и круглые скобки ##

Приоритет оператора ?? достаточно низкий (равен 3 в официальной спецификации) — он вычисляется раньше присваивания = и тернарного знака ?, но уступает стандартным арифметическим операциям вроде сложения или умножения. При использовании ?? внутри математических выражений круглые скобки являются строго обязательными, иначе умножение или сложение выполнится в первую очередь, исказив логику программы:

```
let height = null;
let width = null;

// Правильный синтаксис со скобками:
let area = (height ?? 100) * (width ?? 50); // 5000

// Без скобок движок сначала выполнит умножение 100 * width:
let areaWrong = height ?? 100 * width ?? 50; // сработает как height ?? (100 * width) ?? 50
```

## Запрет на совместное использование ##

Из соображений безопасности и во избежание логических багов при переходе разработчиков со старого синтаксиса на новый, JavaScript на уровне спецификации запрещает использовать ?? в одной строке с && или || без явного указания приоритета. Попытка написать такой код без изоляции приведет к падению скрипта с синтаксической ошибкой:

```
// let x = 1 && 2 ?? 3; // SyntaxError: Нельзя смешивать без скобок

let x = (1 && 2) ?? 3; // Работает корректно
alert(x); // 2
```

## Оператор нулевого присваивания (??=) ##

Оператор нулевого присваивания ??= позволяет сократить объем кода, когда необходимо записать дефолтное значение в переменную только в том случае, если она пуста (null или undefined). Конструкция x ??= y проверяет левый операнд, и если он определен, правая часть выражения игнорируется и сопутствующие функции (например, alert) даже не запускаются:

```
let userAge = null;
userAge ??= 18;
alert(userAge); // 18 (значение перезаписалось)

let globalAge = 18;
globalAge ??= alert("не сработает"); // alert проигнорирован, так как globalAge определен
alert(globalAge); // 18
```

Эта запись полностью заменяет собой стандартный условный блок:

```
if (userAge === null || userAge === undefined) {
  userAge = 18;
}
```
